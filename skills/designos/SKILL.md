# DesignOS Skill

## Purpose
Move a product from idea/PRD/reference to approved design direction, validated implementation, and launch-ready visual assets.

## Mandatory workflow
1. Normalize PRD, prompt, URL, screenshot, or existing product into a project.
2. Ask only questions that materially change design decisions.
3. Search project memory, semantic cache, and the Design Vault before live research.
4. Route live research to a targeted subset of sources; never search the whole catalog by default.
5. Convert references into Design DNA: layout, hierarchy, typography, spacing, palette, imagery, interaction, motion, responsive behavior, technology, reusable principles.
6. Reinterpret useful principles through the approved brand; do not blindly clone finished references.
7. Create a moodboard and require approval before storyboard.
8. Create a storyboard and require approval before implementation.
9. Persist keep / modify / reject decisions.
10. Default to progressive retrieval (L0 metadata, L1 micro-summary, L2 Design DNA, L3 fragments, L4 raw artifact).
11. Reuse exact/semantic cache and use Caveman compression when available.
12. Enforce Token Governor budgets.
13. Install selected third-party component dependencies only inside the target project/sandbox.
14. Validate implementation against approved moodboard/storyboard/brand rules.
15. Support Production Studio: brand kit, mockups, store screenshots, launch assets, video, prompt packs.

## Approval gates
Moodboard approval is mandatory before storyboard. Storyboard approval is mandatory before implementation. Public production publishing remains user-controlled.

## Reference handling
Inspect public or legitimately licensed material to understand design/implementation principles. Do not bypass paywalls, authentication, license checks, or access controls.

## Token discipline
SEARCH LESS. RETRIEVE LESS. SEND LESS. REASON FROM STRUCTURED KNOWLEDGE. EXPAND ONLY WHEN NECESSARY.
